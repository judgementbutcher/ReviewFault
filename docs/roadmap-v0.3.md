# v0.3 后端与间隔学习升级计划

v0.2.3 先解除 Windows 安装阻断；v0.3.0 再以“可回放、可度量、可迁移”为前提升级后端与
间隔学习算法。前端信息架构维持稳定，只增加解释调度结果所必需的反馈。

## 1. 建立算法基线与验收指标

- 从不可变 `review_event_v2` 生成匿名的本地回放数据，不上传题目、答案或图片；
- 增加离线评估命令，逐事件重放 408 与数学历史，输出召回率、遗忘次数、日负载峰值、
  间隔分布和预测校准误差；
- 冻结 v0.2 参数的基线报告。新算法必须在黄金样例、真实历史回放和极端边界三类数据上通过，
  不能只凭公式升级。

## 2. 后端与数据契约 v3

- 新增 schema v3 迁移，保留原始事件并增加算法决策快照、客户端时区偏移、作答耗时质量标记；
- 建立参数注册表：算法名、算法版本、参数版本、校验和和生效时间都随事件持久化；
- 备份协议升级到 v3，同时继续恢复 v1/v2；恢复失败必须事务回滚并保留原库；
- Android JNI、Windows P/Invoke 与 C ABI 同步升级到 v3，v2 入口只用于历史回放。

## 3. 408 调度升级

- 先用当前 FSRS-6 参数做预测校准，区分“短步骤学习”和“长期复习”事件；
- 只有在用户历史量达到最低阈值且回放指标优于默认参数时，才启用个人参数；数据不足时继续使用
  冻结默认参数，避免小样本把间隔推向极端；
- 对逾期卡、连续遗忘和同日重复作答增加专门的回归样例，并约束最大日负载与最大间隔。

## 4. 数学调度升级

- 将错因、提示使用、作答耗时与连续熟练次数纳入回放分析，但不直接把耗时等同于掌握程度；
- 分别评估概念/思路错误与计算/审题/超时错误的重做间隔，参数变化必须提升后续独立完成率；
- 保留章节交错约束，并增加“近期连续失败优先、同章节不过度连出、长期已熟练逐步拉长”的负载测试；
- 数学参数独立版本化，不与 408 的 FSRS 参数共用版本号。

## 5. 发布门禁与灰度

- 每次 schema、ABI、备份或参数变更都必须同步提升对应版本并补迁移/兼容测试；
- Android 与 Windows 对同一回放输入必须逐字段一致；5,000 条题目下队列生成需满足性能预算；
- 先提供“使用 v0.3 调度/继续 v0.2 参数”的本地开关，并记录可逆的算法版本，不重写旧事件；
- 完成 Windows 10/11、Android API 26/35、双端互备份和升级安装验证后再打 `v0.3.0` tag。

## 交付顺序

1. 回放工具与基线报告；
2. schema/备份/C ABI v3；
3. 408 参数训练与保护阈值；
4. 数学调度参数实验与黄金样例；
5. 双端接入、灰度开关、真机验证和 v0.3.0 发布。
