# ReviewFault DSR v1 调度器

## 设计目标

算法使用“难度（Difficulty）—稳定性（Stability）—可提取率（Retrievability）”模型。它吸收了现代间隔重复算法的核心思想，但本版本是 ReviewFault 自己的、参数固定且有测试的规则，不冒充某一版 FSRS 实现。

- 难度 `D`：1（容易）到 10（困难）；
- 稳定性 `S`：以天计，表示可提取率衰减到 90% 所需的时间尺度；
- 可提取率 `R`：复习当时成功回忆的估计概率；
- 目标保留率：默认 90%，可配置为 80%–97%。

经过 `t` 天后：

```text
R(t, S) = (1 + 19/81 * t/S)^(-0.5)
```

选择下次间隔时反解此式，使到期时 `R` 等于目标保留率。稳定性越大，间隔越长；目标保留率越高，间隔越短。

## 四档评分

- `Again`：没有回忆成功；进入学习/再学习，10 分钟后重试；
- `Hard`：回忆成功但明显困难；稳定性小幅增长；
- `Good`：正确且付出正常努力；
- `Easy`：快速、确定地正确；稳定性增长最大。

新内容使用固定的经过验证的起始尺度：Again 0.12 天、Hard 0.5 天、Good 2 天、Easy 5 天。首次 Again/Hard 留在学习阶段；Good/Easy 毕业到复习阶段。

复习成功时，越接近遗忘边缘（`R` 越低）所带来的稳定性增益越大；过早复习不会获得同等增益。失败会增加难度、降低稳定性并累计 lapse。所有参数集中在实现中，并由行为测试约束。未来可在有足够匿名学习历史后拟合参数，但 ABI 版本变化必须迁移或保留旧算法。

## 重要约定

- 调度器只处理时间间隔，不决定一天内队列顺序；
- `Hard` 是“成功但困难”，不能用作“稍后再看”；跳过不产生复习日志；
- 已到期内容允许逾期；算法按真实经过时间计算，而不是按原定间隔假装准时；
- 输出到期时刻是绝对 UTC 秒；客户端不得再按本地午夜改写；
- 评分一旦保存即形成不可变日志。首版不提供撤销；后续只能通过显式补偿事件纠正，不能覆盖原历史。
